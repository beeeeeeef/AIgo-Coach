# Algo-Coach 项目文档

## 1. 项目定位

Algo-Coach 是一个面向算法刷题场景的 AI 教练工具。

### 产品形态

- **浏览器插件**（Edge/Chrome）：LeetCode 页面集成，自动抓取题目
- **Web 管理面板**：用户登录、AI 配置管理、对话历史查看
- **后端服务**：用户认证、Agent 逻辑、AI 配置加密存储

### 核心能力

1. **自动抓取题目信息**：识别 LeetCode 中文站题目页，自动提取标题、描述、URL
2. **多轮对话式教练**：基于上下文的连续对话，给提示不给答案
3. **代码分析和建议**：分析用户代码的逻辑问题、复杂度、优化方向
4. **自定义大模型配置**：支持用户配置 OpenAI、DeepSeek、Claude 等多个提供商

### 一句话定位

> 在 LeetCode 中文站刷题时，通过多轮对话帮用户理解题目、发现代码问题、获得下一步提示的 AI 算法教练。

## 2. 系统架构

### 2.1 整体架构

```
┌─────────────────────┐
│  浏览器插件         │
│  - 抓取 LeetCode    │
│  - 聊天界面         │
│  - 调用后端 API     │
└──────────┬──────────┘
           │ HTTPS
           ↓
┌─────────────────────┐      ┌──────────────────┐
│   后端服务 (Go)     │──────│  前端 Web 面板   │
│  - 用户认证 (JWT)   │      │  - 登录/注册     │
│  - AI 配置管理      │      │  - AI 配置管理   │
│  - Agent 核心逻辑   │      │  - 对话历史      │
│  - 对话历史存储     │      │  - 使用统计      │
└──────────┬──────────┘      └──────────────────┘
           │
           ↓
┌─────────────────────┐
│   PostgreSQL        │
│  - users            │
│  - user_ai_configs  │
│  - conversations    │
└─────────────────────┘
           │
           ↓
┌─────────────────────┐
│  大模型 API         │
│  - OpenAI           │
│  - DeepSeek         │
│  - Claude           │
└─────────────────────┘
```

### 2.2 三端职责

#### 浏览器插件
- **Content Script**：识别 LeetCode 页面，抓取题目信息
- **Popup**：聊天式对话界面
- **Background**：管理登录状态、API 调用
- **Settings**：快捷配置入口（跳转 Web 管理面板）

#### 前端 Web
- 用户注册/登录
- AI 配置管理（增删改查、设置默认）
- 对话历史查看和管理
- 使用统计和数据分析

#### 后端服务
- 用户认证和授权（JWT）
- AI 配置 CRUD + API Key 加密存储
- Agent 核心逻辑（构建提示词、调用 LLM、工具调用）
- 对话历史持久化
- 动态创建不同提供商的 AI 客户端

### 2.3 核心使用场景

**场景 1：首次使用**
```
1. 用户访问 Web 面板注册账号
2. 登录后配置 AI（输入 OpenAI API Key）
3. 安装浏览器插件
4. 插件内登录（复用 Web 登录 Token）
5. 开始在 LeetCode 使用
```

**场景 2：日常刷题**
```
1. 用户在 LeetCode 中文站打开题目页
   https://leetcode.cn/problems/two-sum/
   
2. 插件自动识别页面并抓取题目信息

3. 用户点击插件图标，打开聊天界面

4. 用户输入："这道题我不知道怎么优化"

5. 插件调用后端 /api/agent/chat
   - 携带题目上下文
   - 携带用户代码
   - 携带对话历史

6. 后端 Agent：
   - 从数据库加载用户的默认 AI 配置
   - 解密 API Key
   - 构建教练提示词
   - 调用大模型 API
   - 返回教练式回复

7. 插件展示回复，用户继续对话
```

## 3. 第一版产品原则

### 3.1 教练模式优先

Algo-Coach 第一版默认采用“教练模式”，不是“题解模式”。

教练模式应该做到：

- 指出用户当前思路的问题
- 给出下一步思考方向
- 提醒可能的数据结构或算法方向
- 解释为什么当前代码可能错
- 尽量不直接给完整 AC 代码

不应该默认：

- 直接贴完整题解
- 直接给最优代码
- 直接替用户完成整道题

### 3.2 场景优先，不做通用聊天

第一版只解决一个明确场景：

> LeetCode 中文站题目页面中的一键算法辅导。

暂不做：

- 通用 AI 聊天
- 多网站支持
- 大而全学习平台
- 用户画像
- 排行榜/社区功能

### 3.3 先跑通闭环，再做账号系统

v0.1 重点是验证核心闭环：

```txt
插件能否抓取题目信息？
AI 能否基于题目和代码给出有用提示？
用户是否愿意在刷题时使用？
```

因此 v0.1 可以暂时不做完整登录注册。

## 4. v0.1 核心功能

### 4.1 Edge 浏览器插件

#### 功能 1：识别 LeetCode 中文站题目页

插件需要判断当前页面是否是 LeetCode 中文站题目页。

目标 URL 示例：

```txt
https://leetcode.cn/problems/two-sum/
https://leetcode.cn/problems/two-sum/description/
https://leetcode.cn/problems/two-sum/submissions/
```

只在符合以下条件时启用分析：

```txt
域名：leetcode.cn
路径包含：/problems/
```

#### 功能 2：抓取题目信息

插件从当前页面抓取：

- 题目标题
- 题目 URL
- 题目描述文本
- 示例输入输出
- 约束条件

v0.1 可以先使用 `innerText` 抓取主要题面，不追求完美结构化。

#### 功能 3：获取用户代码

LeetCode 中文站的代码编辑器可能是 Monaco Editor，不一定能通过普通 textarea 直接获取。

v0.1 推荐策略：

- 自动抓取题目
- 代码区域先允许用户手动粘贴
- 后续版本再研究自动读取编辑器内容

这样可以避免第一版卡死在编辑器 DOM 解析上。

#### 功能 4：插件弹窗或侧边栏展示

插件 UI 第一版包含：

- 当前页面识别状态
- 当前题目标题
- 代码输入框
- 分析按钮
- AI 返回结果展示区

第一版可以先用 popup，后续如果内容较长，再升级为 side panel。

---

### 4.2 后端分析接口

后端提供一个最小接口：

```http
POST /api/analyze
```

请求示例：

```json
{
  "site": "leetcode-cn",
  "problemTitle": "两数之和",
  "problemUrl": "https://leetcode.cn/problems/two-sum/",
  "problemText": "给定一个整数数组 nums 和一个整数目标值 target...",
  "language": "cpp",
  "code": "class Solution { ... }",
  "mode": "coach"
}
```

响应示例：

```json
{
  "success": true,
  "data": {
    "summary": "你现在的思路接近暴力枚举，可以解决小数据，但复杂度较高。",
    "issues": [
      "当前做法需要两层循环，时间复杂度是 O(n^2)",
      "没有利用 target - nums[i] 这个关键信息"
    ],
    "hints": [
      "思考：遍历到 nums[i] 时，你真正需要找的另一个数是什么？",
      "是否可以用一个结构记录之前见过的数字？",
      "如果能在 O(1) 时间判断某个数是否出现过，复杂度会变成多少？"
    ],
    "complexityComment": "目标方向通常可以做到 O(n) 时间复杂度。"
  },
  "error": null
}
```

## 7. v0.1 开发顺序

### 阶段 1：插件原型

目标：插件能在 LeetCode 中文站识别题目页面。

任务：

1. 创建 `extension/` 项目
2. 编写 `manifest.json`
3. 编写 content script
4. 判断当前 URL 是否是 LeetCode 中文站题目页
5. 抓取题目标题和页面文本
6. 在 popup 中显示抓取结果

验收标准：

- 打开 LeetCode 中文站题目页
- 点击插件
- 能显示当前题目标题和部分题面文本

---

### 阶段 2：后端最小分析接口

目标：后端可以接收题目信息和代码，并返回模拟分析结果。

任务：

1. 创建 `/api/analyze`
2. 定义请求 DTO
3. 定义响应 DTO
4. 先返回 mock 数据
5. 插件调用该接口

验收标准：

- 插件点击“开始分析”
- 后端收到请求
- 插件能展示后端返回的 mock 分析结果

---

### 阶段 3：接入大模型

目标：后端真实调用大模型，返回教练式分析。

任务：

1. 在后端配置 API Key
2. 封装 AI Client
3. 设计 coach prompt
4. 将题目、代码、语言、模式传给大模型
5. 返回结构化结果或纯文本结果

验收标准：

- 对 LeetCode 题目点击分析
- 返回内容与题目和代码相关
- 默认不直接给完整答案

---

### 阶段 4：体验优化

目标：让插件更像一个可用工具。

任务：

1. 增加 loading 状态
2. 增加错误提示
3. 支持选择分析类型：
   - 给提示
   - 找 bug
   - 优化复杂度
4. 保存最近一次分析结果
5. 优化结果排版

## 8. Coach Prompt 初版原则

系统提示词方向：

```txt
你是一个算法学习教练。你的任务不是直接给用户完整答案，而是帮助用户理解题目、发现思路问题、获得下一步提示。

请遵守：
1. 优先指出用户当前代码或思路的问题。
2. 给出分层提示，从轻提示到强提示。
3. 不要默认给完整 AC 代码。
4. 如果用户代码明显错误，指出最关键的 1-3 个问题。
5. 如果用户没有提供代码，则只讲思路方向，不直接给完整实现。
6. 使用中文回答。
```

输出结构建议：

```txt
## 当前判断

## 主要问题

## 下一步提示

## 复杂度方向

## 你可以先尝试这样改
```

## 9. 关键风险

### 风险 1：LeetCode 页面结构变化

LeetCode 中文站是 SPA 页面，DOM 结构可能变化。

应对：

- v0.1 使用相对稳妥的文本抓取
- 不过早追求完美结构化
- 将 LeetCode 抓取逻辑集中在 `content/leetcode-cn.ts`

### 风险 2：自动读取代码困难

LeetCode 编辑器不是普通 textarea。

应对：

- v0.1 允许用户手动粘贴代码
- 后续再探索 Monaco Editor 自动读取方案

### 风险 3：AI 直接泄题解

如果 prompt 控制不好，AI 可能直接给完整答案。

应对：

- 默认 coach 模式
- prompt 中明确禁止默认给完整 AC 代码
- UI 中单独设置“查看完整题解”作为后续功能，而不是默认行为

### 风险 4：范围膨胀

容易同时想做登录、画像、多模型、多网站。

应对：

- v0.1 只做 LeetCode 中文站 + 插件 + `/api/analyze`
- 登录注册和画像全部后置

## 10. v0.1 成功标准

v0.1 成功不是代码量大，而是能跑通一个真实场景：

```txt
用户打开 LeetCode 中文站题目页
→ 点击 Edge 插件
→ 插件识别题目
→ 用户粘贴当前代码
→ 点击分析
→ AI 返回有用的教练式提示
```

如果这个流程顺畅，项目方向成立。

如果这个流程不好用，应优先改这个闭环，而不是增加登录注册、画像、多模型等外围功能。
